## Previously unresolved HTML tables — exact live sources

### Admin

- **Departments, both tables:** `app/(app)/admin/phong-ban/page.tsx:10-24` calls `listDepartments()` and `listAllUsersForAdmin()`. Both are full-set: departments include real `_count.members`, `orderBy code asc`; users select scalar flags/FK and `orderBy name asc` (`lib/department-service.ts:11-18,51-63`). Schema is flat `User.departmentId -> Department`, not a parent/child department hierarchy (`prisma/schema.prisma:9-81`). Department table displays `code/name/memberCount/isActive`; member table displays `name/email/role`, department choice label `code - name`, leader/director flags (`app/(app)/admin/phong-ban/department-client.tsx:190-205,253-286`).
- **Import history:** page calls `getRuns()` (`app/(app)/admin/import/page.tsx:6-10`), which hard-limits `listImportRuns(50)` (`import-actions.ts:16-20`) → `ImportRun.findMany orderBy createdAt desc, take:50` (`lib/import/import-engine.ts:161-166`). This is server-limited, not full-set, and has no count. Labels/values are id, filename, adapter, status badge, imported/skipped counts, localized created time (`admin/import/page.tsx:42-70`).
- **Import detail errors:** `getRun(id)` is a single `findUnique` with the complete JSON `errors` column (`import-actions.ts:22-25`; `import-engine.ts:169-171`; schema `prisma/schema.prisma:917-930`). The table renders the entire decoded error array, with displayed row number `rowIndex+1` and message (`admin/import/[runId]/page.tsx:15-18,71-88`); no query limit/order exists beyond JSON array order.
- **Roles:** `RolesPage` calls `listRoles()` then one `getRoleWithPermissions` per role (`roles/page.tsx:6-17`). Roles are full-set `orderBy id asc`, permission count is real `_count`, user count is computed from full `User.groupBy(role)` (`lib/admin/role-service.ts:28-53`). Display is name/id/moduleCount/userCount (`roles-client.tsx:76-93`).
- **Module permission matrix:** full-set users `orderBy name asc` plus full `modulePermission.findMany`, no limit/count (`permissions/modules/page.tsx:11-25`). `User.department` is a real relation used for `deptName` (`:38-43`); columns are fixed `GRANTABLE_MODULE_KEYS`, rows show name and computed `role · deptName`, cells show access-level labels (`module-permission-grid.tsx:191-251`).
- **Project permission panel:** full-set users and projects (`name asc` each), plus all `ProjectPermission` and `ProjectGrantAll` rows; no limit/count (`permissions/projects/page.tsx:7-28`). `ProjectPermission` is the real composite `userId/projectId` relation (`prisma/schema.prisma:1360-1373`). User rows display fallback name, role, department and computed grant-all; inner project rows display project name/code and mapped permission level (`project-permission-panel.tsx:286-310`).
- **User grants:** page calls `listUsersWithGrants`, active departments, roles (`admin/nguoi-dung/page.tsx:9-20`). All are full-set: users `name asc` including real `department` and `deptAccess.dept` relations (`lib/admin/user-grants-service.ts:25-54`); departments `code asc` (`department-service.ts:11-18`); roles `id asc` (`nguoi-dung/page.tsx:14`). Display includes identity/status/role/department/flags plus derived grant labels `dept.name` and access-level label (`user-grants-client.tsx:76-96,415-432`).
